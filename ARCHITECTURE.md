## 1. Data Flow Overview

A book enters the system as a PDF and exits as a fully searchable, AI-interactive web page. The journey involves five stages:

```
Upload & Validate
       ↓
OCR & Text Extraction  (Azure Document Intelligence or PyMuPDF)
       ↓
TOC Extraction         (Arabic/English extractors or AI-generated)
       ↓
Database Save          (Book + Author + Category + Sections + Pages)
       ↓
File Generation        (HTML + Markdown + JSONL → Azure Blob Storage)
       ↓
Summarization          (DeepSeek LLM → section + book-level summaries)
       ↓
Embeddings             (OpenAI text-embedding-3-small → pgvector chunks)
       ↓
Live on Library        (AI search + chat enabled)
```

Each stage is handled by a separate FastAPI router and can be triggered independently from the admin panel. A book is usable after the Database Save step, but full AI features require Summarization and Embeddings to complete.

### 2.4 `sections`

One row per TOC chapter/section. Content holds the full extracted text for that section.

| Column | Type | Notes |
|--------|------|-------|
| id | Integer PK | Auto-increment |
| book_id | Integer FK | → books.id (CASCADE delete) |
| title | String(500) | Section/chapter heading |
| level | Integer | TOC depth (1 = top-level chapter) |
| page_start | Integer | First page of section |
| page_end | Integer | Last page of section |
| content | Text | Full extracted text for this section |
| summary | Text | AI-generated summary (DeepSeek) |
| embedding | Vector(1536) | OpenAI embedding of section content |
| order_index | Integer | Display order within book |

### 2.5 `section_chunks`

Smaller chunks of text used for RAG (Retrieval-Augmented Generation). A single section may produce multiple chunks.

| Column | Type | Notes |
|--------|------|-------|
| id | Integer PK | Auto-increment |
| book_id | Integer FK | → books.id (CASCADE delete) |
| section_id | Integer FK | → sections.id (nullable) |
| chunk_index | Integer | Special values: `-2` = book metadata, `-1` = section title only, `0+` = content chunks |
| content | Text | Chunk text |
| embedding | Vector(1536) | OpenAI text-embedding-3-small (1536 dimensions) |

**chunk_index convention:**
- `-2` — Book-level metadata chunk (title, author, description)
- `-1` — Section title-only chunk (for heading-based retrieval)
- `0, 1, 2, …` — Content chunks in order

## 3. Azure Storage Map

All files are stored in Azure Blob Storage. The naming convention for every container is:

```
{book_id}/{filename}
```

Example: book ID 42, filename `book.html` → blob path `42/book.html`

| Container | Content | Typical Filename | Notes |
|-----------|---------|-----------------|-------|
| `books-pdf` | Original uploaded PDF | `{original_filename}.pdf` | Source of truth; used for PDF download feature |
| `books-images` | Cover images | `cover.jpg` | Supports .jpg, .jpeg, .png, .gif, .webp |
| `books-html` | Generated HTML web page | `book.html` | Served directly to readers |
| `books-markdown` | Generated Markdown | `book.md` | Export format |
| `books-json` | JSONL data exports | `book_pages.jsonl`, `book_sections.jsonl` | Structured data for external use |

### JSONL File Formats

**`book_pages.jsonl`** — one JSON object per line, one line per page:
```json
{"page": 1, "has_text": true, "image_count": 0, "text": "extracted text..."}
{"page": 2, "has_text": false, "image_count": 2, "text": null}
```

**`book_sections.jsonl`** — first line is metadata, then one line per section:
```json
{"type": "metadata", "book_id": 5, "book_title": "...", "author": "...", "language": "ar", "num_pages": 200}
{"section_id": "1", "title": "الفصل الأول", "level": 1, "page_start": 1, "page_end": 15, "content": "..."}
```

### Access

Containers are **private**. Public access is provided via:
- **SAS URLs** (Shared Access Signatures) — generated on-demand, expire after 1 hour
- **Server-side proxy** — the app fetches from Azure and serves to the client (used for HTML book pages)

## 4. Processing Pipeline

### Step 1 — Upload & Validate (`app/routers/upload.py`)

- Validates PDF file signature
- Detects language using FastText (fast, offline) or Azure Document Intelligence (accurate)
- Classifies each page: `image_only`, `text_only`, or `mixed`
- Triggers OCR if Arabic or scanned pages detected

**Arabic detection:** If Arabic character ratio > `ARABIC_RATIO_THRESHOLD` (default 0.3), book is classified as Arabic and Azure OCR is forced.

### Step 2 — Text Extraction

| Book Type | Extractor | Notes |
|-----------|-----------|-------|
| Arabic PDF | Azure Document Intelligence | Handles scanned/handwritten Arabic |
| English PDF | PyMuPDF | Fast, free, no API call needed |
| Scanned (any language) | Azure Document Intelligence | Fallback when native extraction yields gibberish |

Gibberish detection runs on a sample of pages. If the extracted text looks like noise, the system falls back to Azure OCR.

### Step 3 — TOC Extraction

Two modes, selected by admin at upload time:

| Mode | How it works |
|------|-------------|
| `extract` | Reads existing PDF bookmarks, or uses language-specific heading patterns |
| `generate` | Sends page text to AI (Azure Document Intelligence) to identify headings |

Admin provides: start page, end page, and page offset for the TOC.

### Step 4 — Database Save

Creates or updates:
- `authors` record (upsert by name)
- `categories` record (upsert by name)
- `books` record with all metadata and file URLs
- `sections` records (one per TOC entry)
- `pages` records (one per PDF page)

Uploads PDF and cover image to Azure at this step.

### Step 5 — File Generation (`app/routers/generation.py`)

Triggered manually from admin panel after upload.

- Generates structured **HTML** web page from sections
- Generates **Markdown** export
- Exports **JSONL** files (pages + sections)
- Uploads all files to Azure
- Updates `books.html_url`, `markdown_url`, `pages_jsonl_url`, `sections_jsonl_url`, `files_generated_at`

### Step 6 — Summarization (`app/routers/summarization.py`)

Triggered manually from admin panel. Runs as background task.

- DeepSeek LLM generates a summary for each section
- Summaries are rolled up into a full book summary
- Updates `sections.summary` and `books.summary` + `books.summary_generated_at`

**Model:** `deepseek-chat` (configurable via `SUMMARIZATION_MODEL`)

### Step 7 — Embeddings / RAG (`app/routers/rag.py`)

Triggered manually from admin panel. Required for AI chat to work.

- Text is chunked: Arabic = 200 words, English = 400 words (with 25/50-word overlap)
- Each chunk is embedded using OpenAI `text-embedding-3-small` (1536 dimensions)
- Special chunks created: book metadata (index -2) and section titles (index -1)
- Stored in `section_chunks` table with pgvector embeddings

**Retrieval at query time:**
1. User question → embedded → cosine similarity search in `section_chunks`
2. Top-k chunks retrieved → sent to GPT-4o-mini with question
3. Answer returned with source citations (section title + page range)

## 5. Environment Variables

All variables are loaded from `.env` via Pydantic Settings (`app/core/config.py`).

### Required

| Variable | Purpose |
|----------|---------|
| `DATABASE_URL` | PostgreSQL connection string |
| `AZURE_STORAGE_CONNECTION_STRING` | Azure Blob Storage authentication |
| `AZURE_DOCUMENT_INTELLIGENCE_ENDPOINT` | Azure OCR endpoint URL |
| `AZURE_DOCUMENT_INTELLIGENCE_KEY` | Azure OCR API key |
| `OPENAI_API_KEY` | Embeddings + answer generation |
| `SECRET_KEY` | Session signing key |
| `ADMIN_USERNAME` | Admin panel login |
| `ADMIN_PASSWORD` | Admin panel password |

| Variable | Default | Purpose |
|----------|---------|---------|
| `DEEPSEEK_API_KEY` | — | Required for summarization |
| `SUMMARIZATION_MODEL` | `deepseek-chat` | LLM model for summaries |
| `SUMMARIZATION_BASE_URL` | `https://api.deepseek.com/v1` | LLM API base URL |

## 6. Data Lifecycle

### Book Status Progression

```
[PDF Uploaded]
      ↓
  Book record created (status: published, is_visible: null/true)
  Sections + Pages saved to DB
  PDF + Cover → Azure
      ↓
  HTML/Markdown/JSONL generated → Azure
  files_generated_at set
      ↓
  Section summaries generated (DeepSeek)
  Book summary rolled up
  summary_generated_at set
      ↓
  Embeddings generated (OpenAI)
  section_chunks populated
      ↓
  [Book fully live — search + AI chat enabled]
```

### Visibility Control

- `is_visible = true` or `null` → book appears in public library
- `is_visible = false` → book hidden from library (admin only)
- `hidden_reason` stores the admin's note for why it was hidden

### Deletion

Deleting a book record cascades to:
- `sections` (and their embeddings)
- `section_chunks`
- `pages`
- `book_feedback`
- `chat_rate_limits`

Azure Blob files (PDF, HTML, Markdown, images, JSONL) are **not automatically deleted** when a book is removed from the database. Manual cleanup in Azure portal is required.

### View Counting

`books.view_count` is incremented on every call to `GET /api/books/{book_id}`. It is never decremented or reset.

### Feedback Lifecycle

Feedback starts as `new`. Admin can move it to `reviewed` (acknowledged) or `resolved` (fixed). There is no automated progression — all status changes are manual from `/admin/feedback`.
